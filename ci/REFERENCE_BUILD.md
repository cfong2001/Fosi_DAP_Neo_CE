# Reproducing the composed source build

The firmware is produced by applying CE patches and separately compiled
payloads to the pinned stock binary; this is not a reconstruction or build
of the vendor's complete original firmware source. The steps below reproduce
the recorded combined image offline once the tools and inputs are present.
Byte-identical output does **not** establish correct playback, memory
coexistence, device slot capacity, update behavior, or hardware safety.
The feature suites that cover playback, theater and transport behavior are
listed in [`patches/full/README.md`](../patches/full/README.md).

The reference toolchain is tested on Linux x86_64 with glibc 2.38 or newer.
It requires `curl`, `sha256sum`, `dpkg-deb`, Python 3.12 and the shared host
libraries used by the downloaded cross-compiler (`libisl`, `libmpc`,
`libmpfr`, `libgmp`, zlib and zstd). Node.js is needed for the browser
payload comparison. These downloads are separate from the vendor firmware:

| Tool | Source and SHA-256 |
| --- | --- |
| GCC 13.2.1, Ubuntu `13.2.rel1-2` | [`gcc-arm-none-eabi_13.2.rel1-2_amd64.deb`](https://archive.ubuntu.com/ubuntu/pool/universe/g/gcc-arm-none-eabi/gcc-arm-none-eabi_13.2.rel1-2_amd64.deb), `519a5d0e5292a4b4861f69ae96e8918149bfd1646072ca53451ccfb8c5a91948` |
| ARM binutils 2.44, Debian `2.44-3+23+b1` | [`binutils-arm-none-eabi_2.44-3+23+b1_amd64.deb`](https://deb.debian.org/debian/pool/main/b/binutils-arm-none-eabi/binutils-arm-none-eabi_2.44-3%2b23%2bb1_amd64.deb), `c9c4944e54de852536b4f6a238a682c38a6243cdc2843dd1c4f587e046c0615b` |

From a clean checkout, install tools into a **new** directory, without system
installation or root access:

```sh
bash ci/install_reference_toolchain.sh /absolute/path/to/new-ce-arm
export PATH="/absolute/path/to/new-ce-arm/usr/bin:$PATH"
python3 -m venv /absolute/path/to/new-ce-venv
/absolute/path/to/new-ce-venv/bin/python -m pip install \
  capstone==5.0.7 keystone-engine==0.9.2 unicorn==2.1.4
```

The installer checks both archive hashes before extraction and refuses an
existing target. Obtain your own decoder `.ecpatch` inputs separately; do not
commit, upload or print their contents. The stock image in the repository
must match `fcc1cd3e35b46f1f8dbcb8da39fcc5eb3f1d469cdfade5e9c6ea3bd71ac6deef`.

Compile and verify the module-31 payload, and compare the generated bytes
with the browser payload and recorded layout:

```sh
cp patches/full/out/layout31.json /tmp/ce-recorded-layout31.json
/absolute/path/to/new-ce-venv/bin/python patches/full/build/build_compose.py \
  --scratch /absolute/path/to/new-scratch
node ci/verify_composed_artifacts.mjs /tmp/ce-recorded-layout31.json
```

The 6,936-byte module-31 SHA-256 must be
`010197e684a8a3e3f1a0937b61fe89a7f620b48c0872e5305f781d42d9b88f05`.
With local decoder inputs, build the complete recorded composition, using an
output path that does not already exist:

```sh
/absolute/path/to/new-ce-venv/bin/python patches/full/build/build_full.py \
  --ecpatch-dir /absolute/path/to/ecpatch-inputs \
  --output /absolute/path/to/new-ce-image.img > /tmp/ce-build.log 2>&1
sha256sum /absolute/path/to/new-ce-image.img
```

The full build prints a large byte-diff report to the log. For the current
recorded composition, the 2,040-byte merged tail SHA-256 must be
`6d77b1102cc4a82828ed8c1670eef99de708565e95d585a58dfdeb1d01047a71`,
and the 13,638,660-byte image SHA-256 must be
`e0bbb61247dc1919646f989ca098bf52fb1da9dfde161d66de983c613089d209`.
These are regression pins for this revision, not permanent hashes for future
changes. Any intentional source or artifact change requires review, updated
pins and regenerated browser data, meaningful behavioral regression tests,
and renewed integration and hardware validation.

Hosted CI recompiles module 31 and checks it against the recorded and browser
payload when the stock image is present. The `firmware.yml` workflow also
fetches the hash-pinned decoder inputs with `ci/fetch_decoder_inputs.sh` and
builds every image through `ci/build_release.sh`; see
[`release/README.md`](../release/README.md). The separate
[`CACHED_IMAGE.md`](CACHED_IMAGE.md) procedure reproduces a recorded binary
from already-generated browser payloads; it is not a source build.
